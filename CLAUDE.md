## 1. Что мы строим

Telegram Mini App для абитуриентов Узбекистана. Предмет — обязательный блок вступительного экзамена: математика, история Узбекистана, родной язык и литература.

Аудитория: школьники 15–18 лет, телефон, слабый интернет, узбекский и русский языки.
Масштаб, под который проектируем: сотни тысяч пользователей, пики в сезон поступления.

Логика продукта: обязательный блок конечен, и мы показываем его целиком. Ученик видит, сколько тем в блоке и сколько он закрыл. Внутри темы — теория, схема, карточки, вопросы. Ошибки копятся сами и разбираются отдельно.

### Железные продуктовые запреты

Нарушение любого из них — это баг, даже если код работает:

1. **Никаких прогнозов балла.** Не считаем «твой балл 21.8 из 33», не показываем «+0.6 балла за сессию». Показываем только факты: сколько тем закрыто, сколько вопросов решено, сколько ошибок не разобрано, сколько дней до экзамена.
2. **Никакого принуждения.** Пользователь ходит куда хочет. Система не блокирует темы и не заставляет проходить по порядку. Но на каждом экране темы всегда есть кнопка «Дальше» на следующую тему по программе.
3. **Никакой дешёвой геймификации.** Нет монет, сундуков, персонажей, десятков бейджей, стриков-угроз.
4. **Никакого выдуманного контента.** Ты не сочиняешь учебный материал. Весь контент приходит из seed-файлов, которые даю я. Если для проверки нужен текст — бери его из `content/seed/` и ниоткуда больше.
5. **Разные механики для разных предметов.** Математика, история и язык рендерятся разными блоками (см. раздел 6). Не делай один универсальный шаблон на три предмета.

## 2. Архитектура: один движок, несколько приложений

Это самое важное архитектурное решение, и оно принимается сейчас, а не потом.

Мы делаем не одно приложение, а семью: обязательный блок, биология, химия, позже физика и математика. У каждого свой Telegram-бот, свой бренд, свой маркетинг. Но код, база, платежи и админка — общие.

Поэтому с первого коммита:

- Приложение конфигурируется через `apps.config.ts`: ключ приложения, название, палитра, список предметов, тексты, токен бота.
- Ключ текущего приложения приходит из переменной окружения `NEXT_PUBLIC_APP_KEY`.
- Нигде в коде не должно быть захардкожено «математика/история/язык». Предметы приходят из конфига и базы.
- Все таблицы контента и прогресса имеют поле `appKey`.

Проверка: чтобы запустить второе приложение (биологию), должно хватить нового конфига, нового бота и нового деплоя — без копирования кода.

## 3. Стек

- Next.js (App Router) + TypeScript в strict-режиме
- Tailwind CSS
- PostgreSQL + Prisma
- TanStack Query для серверных данных, Zustand для локального UI-состояния
- Zod для валидации всего, что приходит извне
- Telegram Mini Apps SDK для интеграции с Telegram
- Vitest для тестов
- Хостинг: Vercel; база: Neon или Supabase (выбери и объясни выбор)
- Пакетный менеджер npm. Среда разработки — Windows, учитывай это в командах и путях

Не добавляй библиотеки, без которых можно обойтись. Каждую новую зависимость обоснуй одной строкой.

## 5. Модель данных

Начни с этой схемы, при необходимости дополни и объясни изменения.

```prisma
model User {
  id            String   @id @default(cuid())
  appKey        String
  telegramId    BigInt
  firstName     String?
  languageCode  String   @default("uz")
  createdAt     DateTime @default(now())
  lastSeenAt    DateTime @default(now())
  progress      Progress[]
  attempts      Attempt[]
  errors        ErrorItem[]
  @@unique([appKey, telegramId])
}

model Subject {
  id       String  @id @default(cuid())
  appKey   String
  key      String              // math | hist | lang
  title    String
  titleUz  String
  order    Int
  classes  Class[]
  @@unique([appKey, key])
}

model Class {
  id        String   @id @default(cuid())
  subjectId String
  title     String
  order     Int
  subject   Subject  @relation(fields: [subjectId], references: [id])
  chapters  Chapter[]
}

model Chapter {
  id      String  @id @default(cuid())
  classId String
  title   String
  order   Int
  class   Class   @relation(fields: [classId], references: [id])
  topics  Topic[]
}

model Topic {
  id         String   @id @default(cuid())
  chapterId  String
  slug       String   @unique
  title      String
  order      Int
  blocks     Json     // массив учебных блоков, см. раздел 6
  published  Boolean  @default(false)
  updatedAt  DateTime @updatedAt
  chapter    Chapter  @relation(fields: [chapterId], references: [id])
  questions  Question[]
}

model Question {
  id          String @id @default(cuid())
  topicId     String
  text        String
  options     Json     // массив строк
  correctIdx  Int
  explanation String
  order       Int
  topic       Topic  @relation(fields: [topicId], references: [id])
}

model Progress {
  id      String   @id @default(cuid())
  userId  String
  topicId String
  status  String   // opened | done | known
  seenAt  DateTime @default(now())
  doneAt  DateTime?
  user    User     @relation(fields: [userId], references: [id])
  @@unique([userId, topicId])
}

model Attempt {
  id          String   @id @default(cuid())
  userId      String
  questionId  String
  chosenIdx   Int
  correct     Boolean
  ms          Int
  createdAt   DateTime @default(now())
  user        User     @relation(fields: [userId], references: [id])
  @@index([userId, createdAt])
}

model ErrorItem {
  id          String   @id @default(cuid())
  userId      String
  questionId  String
  status      String   // open | fixed
  wrongCount  Int      @default(1)
  createdAt   DateTime @default(now())
  fixedAt     DateTime?
  user        User     @relation(fields: [userId], references: [id])
  @@unique([userId, questionId])
}
```

Индексы ставь под реальные запросы: список тем предмета, прогресс пользователя, открытые ошибки.

## 6. Контент как данные

Тема — это массив блоков в поле `blocks`. Каждый блок имеет `type` и свои поля. Рендерер — реестр компонентов: тип блока → React-компонент. Неизвестный тип не роняет страницу, а показывает аккуратную заглушку и пишет предупреждение в лог.

Это ядро проекта: позже я буду заливать контент из учебников именно в этом формате, поэтому схема должна быть строгой и валидируемой через zod.

### Общие блоки

- `text` — абзацы с возможностью подсветки фрагментов
- `rule` — правило в одну строку плюс примеры
- `flashcards` — массив пар вопрос/ответ
- `image` — картинка с подписью (используем редко)

### Математика

- `linkedFormula` — условие задачи и формула, где одинаковые сущности связаны цветом; нажатие на число подсвечивает букву
- `steps` — скелет решения: строки шагов, у каждой раскрывающееся объяснение «почему так»
- `decisionTree` — дерево выбора способа: узлы с вопросом и вариантами, листья с методом и примером
- `firstStep` — задача без решения, выбор первого действия, затем второго

### История

- `timeline` — вертикальная лента событий, точки кликабельны, у каждой пояснение
- `entityCard` — карточка государства или личности с фиксированными слотами: годы, основатель, столица, кто сменил, чем известно, имена
- `letterChain` — мнемоническая цепочка первых букв, буквы кликабельны
- `timeChart` — горизонтальная шкала лет с дорожками (государства, личности, события) и ползунком года; показывает, кто с кем был современником
- `causeEffect` — пары причина → следствие

### Язык и литература

- `morphemes` — слово, разобранное на цветные блоки; каждый блок кликабелен
- `contrast` — экран пополам: два похожих случая, различие подсвечено
- `sentenceParse` — предложение с раскрашенными членами
- `builder` — конструктор слова: собрать из частей в правильном порядке, неверную часть не принимать и объяснять почему
- `workCard` — карточка произведения: автор, век, жанр, герои, о чём

Все блоки должны работать на телефоне, крупными зонами нажатия, без горизонтального скролла.

## 7. Экраны

1. **Главная** — общий счётчик закрытых тем, дни до экзамена, плитки предметов с полосой прогресса.
2. **Предмет** — прогресс, список классов, вход в режим «отметить, что уже знаю».
3. **Класс** — главы и темы, статус каждой темы.
4. **Тема** — вкладки: Теория, Схема, Карточки, Вопросы. Внизу: «Тема пройдена» и «Дальше: следующая тема».
5. **Тесты** — по теме, по классу, полный вариант.
6. **Прохождение теста** — вопрос, варианты, мгновенная проверка, объяснение, итог.
7. **Ошибки** — не разобранные и исправленные, разбор с повторным ответом.
8. **Повторение** — пройденные темы по давности.

Нижняя навигация из четырёх пунктов: Предметы, Тесты, Ошибки, Повторение. На иконке ошибок — счётчик не разобранных.

Дизайн: светлый, чистый, крупные тапы, никакого неона, глассморфизма, тяжёлых градиентов и 3D. Следуй теме Telegram (светлая и тёмная). Пользователь должен понимать следующий шаг за одну-две секунды.

## 8. Безопасность

Это не опция. Без этого не переходим к следующему этапу.

1. **Проверка `initData` на сервере.** Telegram подписывает данные пользователя. Проверяй HMAC-подпись токеном бота на каждом защищённом запросе. Клиенту не верим никогда.
2. **Права только на сервере.** Доступ, прогресс, подписки определяются на бэкенде. Никаких флагов доступа в localStorage.
3. **API не отдаёт весь контент разом.** Только текущая тема и списки без тел уроков. Иначе базу выкачают и запустят копию.
4. **Ограничение частоты запросов** на все публичные эндпоинты.
5. **Секреты только в переменных окружения.** В репозитории — `.env.example` без значений. Токен бота, строка подключения к базе и всё остальное никогда не попадают в git.
6. **Валидация входных данных через zod** на каждом эндпоинте.
7. **Логи без персональных данных.** Не пиши в логи имена и Telegram ID открытым текстом.
8. Собираем минимум данных: Telegram ID, имя, язык. Ни паспортов, ни телефонов, ни адресов.

## 9. Производственные требования

- Списки тем кэшируются и отдаются быстро; контент меняется редко, поэтому используй статическую генерацию или кэш с ревалидацией.
- Прогресс пишется на сервер, но интерфейс не ждёт ответа: оптимистичное обновление плюс откат при ошибке.
- Приложение не должно ломаться при плохой связи: понятные состояния загрузки и ошибок, повтор запроса.
- Ни одного пустого экрана без объяснения: пусто — значит, есть текст, что делать дальше.
- Обработка ошибок: пользователь видит человеческое сообщение, разработчик — стектрейс в логах.
- База: миграции через Prisma, ежедневный бэкап настроен и проверен восстановлением.
- Тесты обязательны для: проверки `initData`, записи прогресса, подсчёта ошибок, импорта контента.
- Событийная аналитика с первого дня: открытие темы, ответ на вопрос (с временем и выбранным вариантом), закрытие темы, старт и конец теста. Без выбранного варианта и времени данные бесполезны.
- Интерфейс с первого дня двуязычный: узбекский и русский. Ни одной строки текста прямо в компонентах — только через словари.

## 10. Этапы

Работай этапами. После каждого — короткий отчёт и остановка на мою проверку.

**Этап 1. Каркас.**
Next.js + TypeScript + Tailwind, `apps.config.ts`, подключение базы, схема Prisma, первая миграция, проверка `initData`, вход через Telegram, пустой экран «Главная» с именем пользователя. Деплой на Vercel и рабочая ссылка внутри бота.

**Этап 2. Контент-движок.**
Zod-схемы блоков, реестр компонентов, три тестовые темы в `content/seed/` (по одной на предмет), скрипты валидации и импорта, экран темы с вкладками.

**Этап 3. Навигация.**
Главная, предмет, класс, тема, счётчики, кнопка «Дальше», режим «отметить, что уже знаю».

**Этап 4. Тесты и ошибки.**
Прохождение теста, запись попыток, автоматическое накопление ошибок, экран ошибок с разбором, экран повторения.

**Этап 5. Отделка.**
Двуязычность, тёмная тема Telegram, состояния загрузки и ошибок, аналитика, скорость.

**Этап 6. Админ-импорт.**
Загрузка контента из JSON пачками, отчёт о том, что импортировано и что не прошло валидацию.

Оплату, подписки и уведомления сейчас не делаем. Но структуру данных проектируй так, чтобы подписка добавлялась без переделки.
